# 无线行人 · 条件转化调整方案（滁州 2023-04-01~07）

> 版本 v1.0 ｜ 2026-11-12 ｜ 方法论源自 NYC 出租车验证框架（2.61 亿行），本文档为无线行人数据集的落地方案
> 配套代码：`extract_trip_stats.py` + `make_adjust_example.py`（本目录）；数据契约见 [输入输出说明.md](./输入输出说明.md)

## 一、背景与目标

NYC 框架已在出租车域完成全链路验证：**基线（晴天查表）× 扰动算子（剂量公式）= 条件分布**，强雨盲测偏差 4%，分层外推 MAE 10.7pp（达到可预测极限）。本方案把该方法论迁移到**无线行人信令数据**：

**核心目标**：给定天气条件（雨强），从晴天基线出发生成雨天行人出行分布（出发时间/距离/速度），并用实测雨天数据对照验证。

**迁移的本质差异**（必须全程携带的红线）：

| | NYC 出租车 | 无线行人 |
|---|---|---|
| 雨对总量的方向 | **+9~31%**（步行者转打车，受益）| **可能相反**（雨压制户外出行）|
| 速度响应 | 变慢（路滑+拥堵）| 待测（可能慢：撑伞；也可能"样本构成变化"）|
| 距离响应 | 短途化 −6% | 待测 |

→ **所有 NYC 系数在本方案中均为"可迁移假设"，第一版图的任务就是量化"假设 vs 实测"的偏差**，为重标提供证据。

## 二、数据资产与约束

| 数据 | 内容 | 状态 |
|---|---|---|
| **轨迹原始 CSV** | 滁州 2023-04-01~04-07（完整一周：工作日+周末）；每行 =（轨迹 id、TimeStamp 13位 UTC ms、经度、纬度）| 在数据机上，本机无 |

| 一周天气实况 | 晴：4/1、4/2、4/7｜**中雨：4/3、4/4（各 29.1mm/日）**｜小雨：4/5（0.9mm）、4/6（2.0mm）| 基线/条件日天然分离 |
| v3 预处理口径 | 轨迹 id 已在数据里，**无需切分**；口径参考 DiffTraj_WireLess_v3_weather | 参考 |

**关键约束**：
1. 仅 7 天 → 晴日基线 n≈3（4/1、4/2、4/7），跨周稳健性弱（NYC 用 288 个干日）
2. 4/3、4/4 为同型中雨日（周一/周二，工作日）——可互为验证（一个标定一个盲测）
3. 温度 6~24°C 无极端档 → 温度维预计平坦（同 NYC 结论），主泛化维=雨强

```
│ (id/时间/经纬度)      (date,hour,rain…) │   │        │                          │
│      └──────┬──────────────┘            │ → │        ▼                          │
│             ▼                            │   │  晴日分型基线(工作日/周末)          │

└──────────────────────────────────────────┘   └────────────────────────────────────┘
```

## 四、四量定义与算子（当前版）

### ① 出发时间 λ(t)

```
基线 = 晴日逐时出发量中位（按日型分组：工作日晴 n=2 / 周末晴 n=1）
合成 = 基线(t) × [1 + 0.052·ln(1 + r_t/0.2)]        ← r_t = 逐时连续雨强（chuzhou2 rain 列）
```

### ② 距离分布 p(d)

```
基线 = 晴日距离样本池化（行人短途为主，中位 ~850m 量级）
合成 = 三旋钮：μ1 −0.061（短途更短）｜w1 +0.025（短途占比↑）｜长途 ×0.9
```

### ③ 速度 v(t)

```
基线 = 晴日逐时中位速度（km/h）
合成 = 基线(t) × exp(−0.025·ln(1 + r_t/0.3))
```

### ④ 空间分布（本版未做，待栅格化）

7 天数据可支持起点栅格份额（v3 的 257 格），列为下一版。

**系数出处声明**：三个算子的全部系数（0.052/0.2、0.025/0.3、三旋钮）为 **NYC 出租车 365 雨时样本标定值**——图上标注"可迁移假设"。

## 五、验证设计（第一版图的核心任务）

| 验证 | 做法 | 判读 |
|---|---|---|
| 逐时出发量对照 | 合成 4/4 vs 实测 4/4（D 列）| 偏差中位 >20% → 系数不可迁移，方向待查 |
| **方向检验（最重要）** | 实测雨时乘子 y(t)=λ雨(t)÷λ基线(t) 的符号 | **y<1（行人被压制）⇔ y>1（转打车）**——NYC 是 y>1，行人若 y<1 则全部符号翻转 |
| 距离/速度对照 | 合成 vs 实测分布（KS/中位偏移）| NYC 的 −6%/变慢是否复现 |
| 互验 | 4/3 标定 → 预测 4/4（两个同型中雨日）| 唯一可做的"盲测"（NYC 用 52 个大雨日）|

## 六、诚实边界

1. **基线 n≈3**：一周数据无跨周稳健性；4/1（周六）、4/2（周日）为周末型，4/7（周五）为工作日型——分型后每组仅 1~2 天
2. **NYC 系数为假设**：行人方向可能相反（见上表），第一版图的 D 列偏差就是重标的启动证据
3. **连续雨强来自再分析数据**（Open-Meteo 风格），非站点实测，量级可信但极值偏保守
4. **7 天无假日/事件**：日型只有工作日/周末两档；节假日、事件档 NYC 结论（换基线/查表）本数据集无法验证

## 七、文件清单与用法

| 文件 | 用途 |
|---|---|
| `extract_trip_stats.py` | 第一步：轨迹+天气 → 统计 JSON（数据机上跑）|
| `make_adjust_example.py` | 第二步：JSON → 调整过程示例图 |
| `make_demo_data.py` | 自检：合成轨迹 + **真实 chuzhou2 天气**驱动全链路 |
| `wireless_stats_demo.json` | 演示统计（schema 同真实输出）|
| `无线行人_调整过程示例_2023-04-04.png` | 自检产出图（合成轨迹+真实天气）|
| `输入输出说明.md` | 数据契约（列名、schema、命令行参数）|

```bash
# 真实数据接入（唯一缺口 = 滁州轨迹 CSV）
python extract_trip_stats.py 滁州raw.csv \
    --weather ../天气数值/chuzhou2_数值天气.csv \
    --dates 2023-04-01,2023-04-07 --out wireless_stats_real.json
python make_adjust_example.py wireless_stats_real.json          # 自动选雨时最多的日子
python make_adjust_example.py wireless_stats_real.json --day 2023-04-04   # 指定条件日
```
