> 两步分离：**提取脚本在存有原始数据的机器上跑**（产出一个小 JSON），**画图脚本任何机器可跑**。

## 第一步：extract_trip_stats.py

### 输入

**① 原始轨迹 CSV**（不切分，轨迹 id 已在数据里）：

| 列 | 类型 | 说明 | 默认列名（可配）|
|---|---|---|---|
| 轨迹 id | str | 同一 id = 一条轨迹 | `AmfUEID` |
| 时间 | int | **13 位 UTC 毫秒**（脚本 `--tz 8` 转北京时间）| `TimeStamp` |
| 经度 | float | | `LongitudeAVG` |
| 纬度 | float | | `LatitudeAVG` |

**② 逐时天气 CSV**（两种格式自动识别）：

**数值版（推荐，已确认配套）**：`天气数值/chuzhou2_数值天气.csv` —— 覆盖 2023-03-31~04-08，正好含数据集一周（4/1~4/7）：

| 列 | 含义 | 用法 |
|---|---|---|
| rain | **连续雨强 mm/h**（最大 8.6）| 直接进 δvol/δv 剂量公式，无档位损失 |
| temperature_2m / apparent_temperature | 气温/体感 | 温度维标定（透传到 JSON）|
| wind_speed_10m / wind_gusts_10m | 风速/阵风 | 风维（透传）|
| relative_humidity_2m / snowfall / visibility / cloud_cover | 湿度/雪/能见度/云量 | 备用 |

**文本版**（v3 `data/<city>/weather.csv`）：date,hour,text → 档位映射（小雨 1.5/中雨 5/大雨 12/暴雨 25 mm/h）。

数据集配套确认：**滁州 2023-04-01~07**，雨日 4/3、4/4（各 29.1mm 中雨）+ 4/5、4/6 小雨。

### 处理（每条轨迹只算一次）

- 出发时刻 = 首点时间（本地时）→ 落入 (日期， 小时) 格
- 行程距离 = **相邻点 haversine 段长累加**（米）
- 速度 = 距离 ÷ (末点−首点)（先 ms→s，再 ×3.6 转 km/h）
- 最简过滤（可配）：点数 ≥2、距离 >50 m、时长 >60 s

### 输出 JSON（schema）

```json
{
  "dates": ["2024-04-01", "...", "2024-04-07"],
  "weather":      {"2024-04-06": ["晴", ..., "中雨", ...]},     // 24 个文本
  "rain_mmh":     {"2024-04-06": [0, 0, ..., 5.0, ...]},        // 24 个雨强
  "n_trips":      {"2024-04-06": [404, 700, ...]},               // 24 个逐时出发量
  "speed_median": {"2024-04-06": [11.1, null, ...]},            // 24 个逐时中位速度 km/h
  "dist_median":  {"2024-04-06": 861.0},                         // 当日中位距离 m
  "dist_samples": {"2024-04-06": [843.2, 921.7, ...]},           // ≤3000 个抽样距离 m
  "trip_count":   {"2024-04-06": 7997}                           // 当日轨迹数
}
```

### 用法

```bash
python extract_trip_stats.py raw.csv \
    --weather weather.csv \
    --id-col AmfUEID --time-col TimeStamp \
    --lon-col LongitudeAVG --lat-col LatitudeAVG \
    --tz 8 --dates 2024-04-01,2024-04-07 \
    --out wireless_stats_0401_0407.json
```

## 第二步：make_adjust_example.py

### 输入
- 统计 JSON（上面的 schema）
- `--day`：条件日（默认自动选雨时数最多的日期）

### 逻辑
1. **基线** = 窗口内晴日按日型分组（工作日晴日均 / 周末晴日均）——4/1~4/7 正好含两种日型
2. **标签实测**：条件日逐时乘子 y(t) = n_trips(雨，时) ÷ 同型基线(时)
3. **合成**（NYC 系数，可迁移假设）：
   - 出发量 ×(1+0.052·ln(1+r/0.2))
   - 距离三旋钮（μ1 −0.061 / w1 +0.025 / 长途 ×0.9）
   - 速度 ×exp(−0.025·ln(1+r/0.3))
4. 三行四列：A 基线 / B 雨强→乘子 / C 调整合成 / D 合成 vs 实测对照

### 输出
`无线行人_调整过程示例_<日期>.png`（出发量/距离/速度 三行；空间分布行待栅格化数据后加）

### 用法

```bash
python make_adjust_example.py wireless_stats_0401_0407.json --day 2024-04-06
```

## 真实数据接入清单（只差一步）

1. 把 4/1~4/7 的原始轨迹 CSV 放到数据机
2. 找到对应城市的天气 CSV（v3 `data/<city>/weather.csv`；**注意四个城市文件日期都不在 4/1~4/7**，需补拉这周的逐时天气）
3. 跑第一步 → 把 JSON 拷回来
4. 跑第二步 → 出图

## 已知边界（图上已标注）

- 系数全部借 NYC 出租车标定值——行人方向可能相反（雨压制户外），须自有数据重标
- 基线 n≈1~5 天（窗口内晴日数），跨周稳健性弱于 NYC 的 288 个干日
- 演示自检已用 chuzhou2 真实数值天气驱动（轨迹为合成）；真实轨迹到位后 D 列对照偏差即是 NYC 系数可迁移性的第一手证据
- 多维就绪：JSON 已透传温度/风速列，后续可加温度维、风维（登记表流水线）
